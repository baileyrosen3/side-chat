# Manual test handoff — Side Chat

The 1.9.2 outline checks cover ARGB opacity, gradient direction, border width, malformed settings, persistence, changes during an active reply, and keyboard toggling/reset. Qt pixel checks verify that pinning preserves the desktop border rather than substituting the UI accent, and that keyboard focus stays outlined when the normal outline is off. Run `QT_QPA_PLATFORM=offscreen QT_QPA_PLATFORMTHEME=generic QT_QUICK_CONTROLS_STYLE=Basic QT_QUICK_BACKEND=software /usr/lib/qt6/bin/qmltestrunner -input tests/qml/tst_outline.qml -import tests/qml/imports -v1`.

On the desktop, compare the open drawer with the active window border, then pin it and open Preferences → Look & Feel. Toggle Outline, close/reopen, and use Reset look. Reload a changed Hyprland border configuration while the drawer is open and while it is closed; the next visible drawer should use the current color, width, alpha, and gradient.

The robot redesign passed 61 Python tests and 9 Qt 6 test cases (including setup/cleanup). Automated rendering covered 19 expression previews, actual surface size, live state transitions, keyboard preview interaction, theme palette changes, and reduced/hidden motion. Rendered expressions were visually inspected. The harness uses fixture colors and no real microphone or agent.

These are the remaining checks for this release. Existing CLI, speech, and computer-control behavior was exercised in earlier releases; the checks below cover how it behaves through the redesigned UI.

| Check | What to do | Expected result |
| --- | --- | --- |
| Flat chat layout | Open chat, send a short message, then a long reply with code. Expand and collapse. | Compact Omarchy font and spacing; flat message rows; readable code; no clipped labels or overlapping controls. The outer body stays connected to the left edge. |
| Theme and scaling | Change Omarchy theme/font and use each monitor. | The robot shell, trim, screen, eyes, antenna, and details all follow live theme colors; captions and controls follow the font and scale. No oversized text or unreadable contrast. |
| Hover controls | Select Jarvis. Hover over the companion, move into the controls, then move away. Click the companion and press Escape. Tab through controls. | Controls appear smoothly, remain reachable, and hide after leaving. Clicking pins them; Escape dismisses them. Keyboard focus is visible. |
| Desktop input | Click and scroll around the companion, especially transparent space and hidden controls. | Underlying apps remain usable outside the visible interaction regions. No invisible large rectangle intercepts input. |
| Position | Drag the companion up and down, including near screen boundaries. Hide/reopen chat, then reload the plugin when idle. | No jump on release; position remains on screen and persists. Opening chat moves the companion to peek around the panel edge. |
| Multiple monitors | Enable Jarvis from each display; open chat on another display; disconnect the companion's display if convenient. | One companion appears on the chosen display and remains recoverable after display removal. |
| Chat/voice lifecycle | While listening, open Conversation, open Settings, close the chat panel, then use the power control. | Opening or closing chat preserves the voice session. Power hides the companion and stops microphone capture and speech. |
| Microphone | Toggle listening. Disable hands-free and wake listening, then hold/release the microphone control. Repeat while dragging the pressed pointer off the button. | Capture starts/stops as expected; releasing outside the button ends the utterance instead of leaving capture active. |
| Standby | Try standby with wake listening off, then with it on. Try it after muting the microphone. Say “go to sleep” and “Hey Jarvis.” | With wake off, standby pauses capture. With wake on, standby resumes keyword listening; the wake word reopens conversation listening. Spoken sleep follows the same rule. Its backend regression tests pass; real audio still needs manual checking. |
| Stop and mute | Start a spoken response/task; try Stop. Toggle spoken-reply mute and unmute. | Stop cancels active work/speech. Reply mute silences TTS without muting your microphone. |
| Companion states | Speak, request a task, trigger a clarification, then finish it. Try reduced motion. | Listening, thinking, working, speaking, attention, and standby states are distinct. The head leans into view on hover and retreats on standby; fingers stay attached to the edge. Eyes follow the pointer; smiles, brows, waves, winks, worried faces, and sleep poses are distinct. Reduced motion suppresses idle/gesture animation. |
| Captions and errors | Speak a long sentence; trigger an agent/model error or approval request. Click its caption. | Captions fit, remain readable, and open the chat for full details or approval controls. Errors remain discoverable when chat is hidden. |
| Desktop/Browser | Choose Desktop and say “open Google”; repeat in Browser mode. | Desktop uses the visible default Omarchy browser. Browser uses isolated headless Chromium. The mode control is disabled during active agent work. |
| Native session | Ask for an edit to a disposable file; redirect the agent mid-task; open Terminal after it finishes. | File/tool actions and approval prompts work in chat; redirection reaches the same agent; Terminal resumes the same conversation. |
| Chat actions | Copy text/code, edit, retry, attach a file/image, search history, export, and start a conversation. | Hover actions are discoverable and keyboard reachable; existing functions still work in the compact layout. Scrolling stays put until Latest is selected. |
| Settings | Open Preferences → Jarvis settings and visit Speech, Listening, Control, and Companion. Save an existing setting, then reopen. | Fields fit and scroll correctly; the saved value persists; model changes and validation feedback remain visible. |

For a quick first pass, prioritize hover controls, microphone, standby, chat/voice lifecycle, and dragging. Report the action, expected behavior, actual behavior, and monitor/theme if the issue is visual.

The previous “Listening but not hearing” report was traced to a design preview that restarted after crashing during shutdown. That preview was terminated and the real Parakeet worker was started. Future previews have an explicit no-microphone label and disabled microphone control. The real worker subsequently completed a voice/agent response. Accuracy for the user’s intended microphone and the new companion’s controls still need the user’s confirmation.

During activation, a separate desktop-shell crash was confirmed in Qt Quick 3D’s `QQuick3DSceneManager::setWindow`, reached while reattaching a viewport to a recreated Quickshell window. Version 1.6.1 keeps the companion’s native window alive and hides its content and input regions instead. Power off/on, repeated opening/closing, and monitor changes need manual checking after this lifecycle fix.
